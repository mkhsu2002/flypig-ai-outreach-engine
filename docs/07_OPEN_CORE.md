# 07 Open Core and Commercial Boundary

FlyPig AI Outreach Engine uses an open-core product strategy.

The public repository is intended to be genuinely useful on its own.

Its purpose is to demonstrate that one capable LLM, guided by explicit process controls, can turn a business-development objective into a persistent, evidence-backed Qualified Prospect Tracker.

## Open-source Core

The public repository includes:

```text
Adaptive Mission Discovery
Tracker setup
Prospect Discovery
Mandatory dedup
Discovery Diversity Check
Account Research
Qualification
Mandatory Prospect Audit
Contact Verification
Qualified Prospect Tracker
Batch self-review
Mission Revision
Stop conditions
Research-state schemas
Cross-chat / cross-agent handoff
Validation / Execution Log support
Optional Knowledge Pack interface
LLM conformance guidance
```

The Open Core stops at the Qualified Prospect Tracker.

## Public promise

A capable user should be able to start from a vague commercial goal and finish with:

```text
A clearer market-development mission
A researched candidate universe
A canonical deduplicated Tracker
Evidence supporting material decisions
A skeptical review of every QUALIFIED prospect
A smaller shortlist-ready set
Recommended professional contact functions
Verified / unresolved / do-not-use contact-route state
Preserved SECONDARY / HOLD / PASS research history
```

## Why this is open

The public value is not a secret prompt or a proprietary runtime.

The Core publishes the operating discipline:

```text
Research before asking
Dedup before insertion
Do not confuse discovery with qualification
Keep facts separate from hypotheses
Challenge premature search-space convergence
Audit qualified prospects skeptically
Review drift during long runs
Version the mission when evidence changes it
Preserve rejected research memory
Know when to stop
```

The underlying LLM provides intelligence. The Open Core provides repeatable process structure.

## Paid commercial layer

FlyPig may separately provide Controlled Outreach capabilities such as:

```text
Account-specific outreach strategy
Formal message preparation
Independent pre-send review
Approval controls
Final pre-send checks
Authorized business-email sending
Confirmed send-state recording
Mailbox / thread monitoring
Reply classification
Bounce and opt-out handling
Controlled follow-up
Execution audit history
```

This execution layer is the primary Free / Paid boundary.

## Knowledge Packs

Knowledge Packs are optional intelligence enhancements rather than the main commercial boundary.

They may add value when they contain defensible information beyond generic LLM knowledge, such as:

```text
Private evaluation cases
Repeated failure patterns
Outcome-backed heuristics
Calibrated thresholds
Market-specific research-source maps
Country / industry distinctions that models handle inconsistently
```

Generic business definitions alone should not be treated as proprietary intelligence.

## Why commercial value remains without a FlyPig runtime

The customer may work in ChatGPT, OpenClaw, Hermes Agents, or another compatible environment.

Real commercial value can come from reliably coordinating:

```text
Exact message versions
Independent review
Approval state
Current recipient state
Duplicate-send prevention
Authorized execution
Mailbox events
Reply interruptions
Bounce / opt-out state
Follow-up timing
Audit history
```

FlyPig does not need to own the underlying LLM runtime or UI.

## Intended relationship

```text
OPEN CORE
Discover → Dedup → Diversify → Research → Qualify → Audit → Verify → Track

PAID CONTROLLED OUTREACH
Strategize → Draft → Review → Approve → Send → Monitor → Follow up
```

## What is not required for the Open Core

```text
FlyPig API
FlyPig SaaS application
FlyPig runtime
FlyPig user interface
Email connector
Multiple AI agents
```
